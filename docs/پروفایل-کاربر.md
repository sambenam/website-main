# پروفایل کاربر

شش تب، همه متصل به داده واقعی.

---

## ۱. مشخصات شخصی

`PATCH /profile/update` — نام، ایمیل، تلفن، تاریخ تولد و آدرس.

**باگی که رفع شد:** تغییرات فقط در `state.profiles` نوشته می‌شد، نه در رکورد حساب. یعنی کاربر نامش را عوض می‌کرد، سشن به‌روز می‌شد، ولی **تب کاربران پنل ادمین همچنان نام قدیمی را نشان می‌داد**. بدتر اینکه سفارش‌ها و پیام‌هایی که با ایمیل تطبیق داده می‌شوند، بی‌صدا از کار می‌افتادند.

حالا هر سه جا همگام می‌شوند: `state.profiles`، `state.users` و انبار پنل.

**اضافه شد:** اگر ایمیل جدید متعلق به حساب دیگری باشد، با خطای `409` رد می‌شود. بدون این، دو حساب با یک ایمیل ساخته می‌شد و لاگین می‌شکست.

---

## ۲. سبد خرید من

**قبلاً:** اگر سبد خالی بود، دو محصول ساختگی نمایش داده می‌شد — «لپ‌تاپ گیمینگ ایسوس» و «هدفون اپل». محصولاتی که این سایت اصلاً نمی‌فروشد. کاربر ۳۳ میلیون تومان کالایی می‌دید که هرگز انتخاب نکرده بود، و «پاک کردن سبد» هم کار نمی‌کرد چون با هر رفرش برمی‌گشتند.

**حالا:** فقط چیزی که واقعاً اضافه شده. سبد خالی، خالی می‌ماند.

**دو باگ دیگر:** شناسه محصولات متنی است (`acc-101`) ولی دکمه‌های کم/زیاد کردن آن را عددی پاس می‌دادند و جاوااسکریپت نامعتبر تولید می‌شد. همچنین موقع تسویه فقط مبلغ کل منتقل می‌شد، نه فهرست محصولات — یعنی گزارش پرفروش‌ها چیزی برای شمردن نداشت.

---

## ۳. سفارش‌های من

هر سه وضعیت — موفق، ناموفق، لغوشده — همزمان در پروفایل کاربر و تب سفارشات پنل ثبت می‌شوند، با همان نام و مشخصاتی که کاربر در پروفایلش دارد.

```
کاربر خرید می‌کند
    ↓
POST /commerce/payment  →  یک رکورد سفارش
    ↓
پروفایل کاربر  +  تب سفارشات پنل ادمین
```

سفارش هر کاربر فقط برای خودش دیده می‌شود (تطبیق با `userId`، نه نام).

## ۴. پیام‌های من

هر سه منبع اینجا جمع می‌شوند:

| منبع           | از کجا              |
| -------------- | ------------------- |
| فرم تماس با ما | صفحه `support.html` |
| پشتیبان هوشمند | ویجت صفحه اصلی      |
| گزارش تخلف     | بخش گزارش تخلف      |

پاسخ مدیر در همان نخ گفتگو می‌نشیند. برای گزارش تخلف، حباب اول شرح گزارش کاربر است و حباب دوم پاسخ مدیر.

## ۵. لیست علاقه‌مندی‌ها

حذف شد — هم تب، هم محتوا. محتوایش هم ساختگی بود (همان لپ‌تاپ و هدفون).

## ۶. امنیت و رمز عبور

**قبلاً:** سه کادر رمز همیشه باز بودند، انگار صفحه از هر بازدیدکننده‌ای می‌خواست رمزش را عوض کند.

**حالا:**

```
رمز عبور فعلی            [چشمک 👁]
─────────────────────────────────
▸ تمایل به تغییر رمز عبور دارم     ← جمع‌شونده
    رمز جدید             [چشمک 👁]
    تکرار رمز جدید        [چشمک 👁]
─────────────────────────────────
[ به‌روزرسانی رمز عبور ]  ← تا ورودی درست نباشد غیرفعال
```

هر سه کادر چشمک دارند. دکمه ثبت تا وقتی رمز کوتاه یا نامطابق باشد غیرفعال می‌ماند و راهنمای زنده می‌گوید مشکل کجاست.

**هشدار شمارش معکوس:** با کلیک روی به‌روزرسانی، پنجره‌ای با شمارش ۵ ثانیه‌ای باز می‌شود. اگر کاری نکنید تأیید می‌شود، ولی می‌توانید انصراف بدهید. از دست دادن رمز با یک کلیک اشتباه، خطای قابل بازگشتی نیست.

---

## ۷. باکس‌های آمار

«امتیاز کل» حذف شد — هیچ چیزی در سیستم امتیاز تولید نمی‌کرد و عدد ۴۵۰ ثابت نوشته شده بود.

دو باکس باقی‌مانده از داده واقعی پر می‌شوند:

- **سفارش‌ها** — از همان فهرستی که جدول سفارش‌ها را می‌سازد
- **سبد خرید** — از تعداد واقعی آیتم‌های سبد

بج کنار نام تب‌ها هم همین‌طور، و وقتی صفر باشد پنهان می‌شود.

---

## برای بک‌اند

```js
PATCH / profile / update; // باید users و profiles را همزمان به‌روز کند
POST / profile / password; // { currentPassword, newPassword }
POST / commerce / my - orders; // فقط سفارش‌های کاربر جاری
POST / support / my - messages; // فقط پیام‌های کاربر جاری، از روی سشن
```

**نکته امنیتی:** `my-orders` و `my-messages` باید کاربر را از **سشن** تشخیص دهند، نه از ایمیلی که در بدنه درخواست آمده. در غیر این صورت هر کسی با فرستادن ایمیل دیگری تاریخچه او را می‌خواند.
