# افزودن سکشن به صفحه اصلی

## بله، ممکن بود — و پیاده شد

## ساختار صفحه اصلی

```
۱. hero-section            🔒 ثابت
۲. learning-path-section   🔒 ثابت — مسیر یادگیری
────────────────────── از اینجا به بعد قابل درج
۳. دوره‌های محبوب
۴. دوره‌های جدید
۵. پیشنهاد ویژه
۶. مقالات
۷. آزمون‌ها و اخبار
```

دو بخش اول عمداً در فهرست «جای قرارگیری» نیستند. یعنی هیچ سکشن جدیدی نمی‌تواند بالای «دوره‌های محبوب» بنشیند.

## چطور کار می‌کند

**در پنل:** تب محتوای سایت ← کارت «سکشن‌های صفحه اصلی» ← افزودن سکشن

| فیلد            | توضیح                                    |
| --------------- | ---------------------------------------- |
| نام سکشن        | عنوانی که بالای بخش دیده می‌شود          |
| جای قرارگیری    | بعد از کدام بخش بنشیند                   |
| آیکون           | از میان ۹ آیکون آماده                    |
| برچسب           | نوشته روی کارت‌ها، مثل «محبوب» (اختیاری) |
| حداکثر نمایش    | چند آیتم نشان داده شود                   |
| لینک مشاهده همه | نمایش داده شود یا نه                     |

**بعد از ساخت:** سکشن یک دسته خالی می‌شود و در فهرست «افزودن آیتم جدید» ظاهر می‌گردد. آیتم‌ها را از همان‌جا به آن اضافه می‌کنید.

## تصمیم‌های طراحی

**سکشن‌های موجود دست‌نخورده ماندند.** پنج بخش فعلی همان مارک‌آپ `index.html` را دارند. سکشن جدید بینشان درج می‌شود، بدون بازنویسی چیزی — کم‌ریسک‌ترین راه.

**قالب مشترک.** سکشن‌های جدید ظاهر «دوره‌های محبوب» را می‌گیرند. سکشن‌های فعلی هرکدام CSS جداگانه دارند (`popular-courses_item`، `articles_item`، …) و تکرار آن الگو برای هر سکشن جدید، نگهداری را سخت می‌کرد.

**سکشن خالی نمایش داده نمی‌شود.** یک عنوان بدون محتوا روی سایت زنده بد به نظر می‌رسد، پس تا وقتی آیتمی نداشته باشد پنهان می‌ماند.

**حذف سکشن، همه‌چیزش را می‌برد.** سکشن، دسته‌اش و آیتم‌های داخلش با هم پاک می‌شوند.

پیش از این فقط سکشن حذف می‌شد و دسته در `siteData` می‌ماند، پس سکشن حذف‌شده همچنان به‌عنوان یک گروه در جدول آیتم‌ها و در فهرست «افزودن آیتم» دیده می‌شد — به نظر می‌رسید حذف کار نکرده است.

پیام تأیید تعداد آیتم‌هایی که از دست می‌روند را می‌گوید:

```
سکشن «دوره‌های پیشنهادی» حذف شود؟

۳ آیتم داخل آن هم حذف می‌شوند. این کار برگشت‌پذیر نیست.
```

## نکته فنی

`home-sections.js` باید **قبل از** `data.js` بارگذاری شود، چون `data.js` دسته‌های سفارشی را از آن می‌خواند. این ترتیب در هر چهار صفحه‌ای که `data.js` دارند رعایت شده است.

## سهم بک‌اند‌کار

```
GET    /api/admin/home-sections
POST   /api/admin/home-sections
PATCH  /api/admin/home-sections/:key
DELETE /api/admin/home-sections/:key
```

شکل سکشن:

```json
{
  "key": "custom_دوره_های_پیشنهادی",
  "title": "دوره‌های پیشنهادی",
  "after": "newCourses",
  "icon": "fa-fire",
  "badge": "پیشنهادی",
  "limit": 6,
  "showAll": true
}
```

`after` باید یکی از این پنج مقدار باشد: `popularCourses` · `newCourses` · `specials` · `articles` · `exams`

⚠️ سرور نباید اجازه دهد `after` مقداری بیرون از این فهرست بگیرد، وگرنه سکشن جایی برای نشستن ندارد.
