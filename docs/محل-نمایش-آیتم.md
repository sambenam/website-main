# محل نمایش آیتم — صفحه اصلی یا صفحه دسته‌بندی؟

## مشکلی که حل شد

قبلاً هر آیتمی که ادمین اضافه می‌کرد، **خودکار به صفحه اصلی می‌رفت** — بدون انتخاب و بدون سقف.

نتیجه: اگر ۱۵ دوره اضافه می‌کردید، بخش «دوره‌های محبوب» که برای ۴ کارت طراحی شده، **۱۹ کارت** نشان می‌داد. بعد از چند ماه صفحه اصلی تبدیل می‌شد به یک لیست بی‌پایان.

## چرا این اشتباه است

صفحه اصلی و صفحه دسته‌بندی دو کار متفاوت دارند:

|           | صفحه اصلی                                 | صفحه دسته‌بندی                                     |
| --------- | ----------------------------------------- | -------------------------------------------------- |
| کارش چیست | **ویترین** — بازدیدکننده تازه را قانع کند | **بایگانی** — کسی که دنبال چیزی می‌گردد پیدایش کند |
| چند آیتم  | ثابت و کم                                 | همه                                                |
| چه چیزی   | دست‌چین‌شده                               | همه‌چیز                                            |

وقتی هر آیتم جدید خودکار به ویترین برود، ویترین کم‌کم تبدیل به بایگانی می‌شود و دلیل وجودی‌اش را از دست می‌دهد.

در سایت‌های واقعی هم همین است: وردپرس محتوای جدید را به آرشیو می‌فرستد، دیجی‌کالا محصول جدید را به دسته‌بندی، یودمی دوره جدید را به لیست دوره‌ها. **هر سه یک پیش‌فرض دارند: آیتم جدید به لیست می‌رود، نه به ویترین.**

---

## چه چیزی عوض شد

### در فرم افزودن آیتم

یک بخش جدید به نام «محل نمایش آیتم» با دو گزینه:

```
◉ فقط صفحه دسته‌بندی            ← پیش‌فرض
○ صفحه دسته‌بندی + صفحه اصلی
```

راهنمای زیر گزینه دوم **زنده** است و با دسته انتخاب‌شده عوض می‌شود.

### سه حالتی که ممکن است ببینید

**۱. دسته در صفحه اصلی بخشی ندارد** (مثل «دیپلم» یا «اکسل»)

گزینه غیرفعال می‌شود و پیام می‌گوید:

> این دسته یکی از منوهای هدر است و در صفحه اصلی نمایش داده نمی‌شود. آیتم در صفحه دسته‌بندی خودش دیده خواهد شد.

از حدود ۳۰ دسته، فقط **۵ تا** در صفحه اصلی بخش دارند.

**۲. بخش جای خالی دارد**

> بخش «مقالات» — ۲ جای خالی از ۴

**۳. بخش پر است** — گزینه همچنان **قابل انتخاب** است، ولی پیام می‌گوید چه چیزی جابه‌جا می‌شود:

> بخش «مقالات» ۴ جا دارد و پر است. اگر این گزینه را انتخاب کنید، آیتم شما اول می‌آید و «آموزش رفع مشکل خطای مربع» از صفحه اصلی کنار می‌رود — ولی در صفحه دسته‌بندی همچنان دیده می‌شود.

بعد از ثبت هم، پیام موفقیت همان نام را تکرار می‌کند تا مطمئن شوید چه اتفاقی افتاد.

## چرا بخش پر مسدود نمی‌شود

این نکته مهمی است. نسخه اول این قابلیت، وقتی بخش پر بود گزینه را **غیرفعال** می‌کرد. با اجرای واقعی معلوم شد این کار قابلیت را کاملاً بی‌فایده می‌کند:

| بخش            | ظرفیت نمایش | آیتم پیش‌فرض موجود |
| -------------- | ----------: | -----------------: |
| دوره‌های محبوب |           ۴ |                  ۸ |
| دوره‌های جدید  |           ۴ |                  ۸ |
| پیشنهاد ویژه   |           ۳ |                  ۸ |
| مقالات         |           ۴ |                  ۹ |
| آزمون‌ها       |           ۴ |                  ۴ |

**هر پنج بخش از همان اول پر هستند.** پس با قانون سختگیرانه، ادمین هیچ‌وقت نمی‌توانست چیزی به صفحه اصلی بفرستد.

قانون درست: **انتخاب صریح ادمین بر پیش‌فرض اولویت دارد.** آیتم شما اول می‌آید و آخرین پیش‌فرض کنار می‌رود. آن پیش‌فرض حذف نمی‌شود — در صفحه دسته‌بندی همچنان هست.

## ظرفیت هر بخش

در `scripts/home-slots.js`:

```js
const HOME_SLOTS = {
  popularCourses: { limit: 4, title: "دوره‌های محبوب" },
  newCourses: { limit: 4, title: "دوره‌های جدید" },
  specials: { limit: 3, title: "پیشنهاد ویژه" },
  articles: { limit: 4, title: "مقالات" },
  exams: { limit: 4, title: "آزمون‌ها و اخبار" },
};
```

این عددها دلبخواهی نیستند — با چیدمان گرید در CSS می‌خوانند. اگر عوض کردید، استایل مربوطه را هم چک کنید.

## سازگاری با آیتم‌های قبلی

آیتم‌هایی که قبل از این تغییر اضافه کرده‌اید، فیلد `homeVisible` ندارند. آن‌ها **همه در صفحه اصلی بودند**، پس نبودِ فیلد به‌معنی «نمایش داده شود» خوانده می‌شود:

```js
function isHomeVisible(item) {
  if (!item) return false;
  return item.homeVisible !== false; // undefined → true
}
```

اگر این را برعکس می‌نوشتم، صفحه اصلی هر سایتی که از این پنل استفاده می‌کند بی‌صدا خالی می‌شد.

---

## برای بک‌اندکار

`homeVisible` یک ستون **boolean** ساده روی رکورد آیتم است.

```json
{
  "id": "custom-article-1",
  "title": "عنوان",
  "categoryKey": "articles",
  "homeVisible": false
}
```

- آیتم‌های قدیمی بدون این ستون: `NULL` را مثل `true` بخوانید
- سقف‌ها قانون نمایشِ سمت فرانت هستند؛ لازم نیست سرور اعمالشان کند
- اگر خواستید سرور هم بررسی کند، منطقش در `scripts/home-slots.js` است

## چیدمان پنجره

پنجره افزودن آیتم قبلاً جعبه پیش‌فرض ۵۰۰ پیکسلی بود با شش فیلد پشت سر هم — باریک و بلند، طوری که دکمه ثبت از پایین صفحه لپ‌تاپ بیرون می‌زد و باید داخل پنجره اسکرول می‌کردید.

حالا **۹۰۰ پیکسل عرض، دوستونه**:

```
+-- مشخصات آیتم -------------+  +-- محل نمایش آیتم ------+
|  شناسه یکتا | دسته هدف     |  |  (o) فقط صفحه دسته‌بندی |
|  عنوان آیتم                |  |  ( ) + صفحه اصلی       |
|  آدرس تصویر شاخص           |  |  [راهنمای زنده]        |
|  خلاصه                     |  +------------------------+
+----------------------------+
          انصراف  |  ثبت آیتم جدید
```

شناسه و دسته کنار هم نشسته‌اند چون هر دو کوتاه‌اند — یک سطر کامل ارتفاع صرفه‌جویی می‌شود. مجموعاً حدود **۲۵۰ پیکسل کوتاه‌تر** شد.

`max-height: 92vh` هم گذاشته شد: روی صفحه کوتاه، **بدنه** اسکرول می‌شود نه کل پنجره، پس سرصفحه و دکمه‌ها همیشه دیده می‌شوند. زیر ۷۸۰ پیکسل عرض، تک‌ستونه می‌شود.

استایلش در `styles/pages/admin-add-item.css` است — از `admin-content-tab.css` جدا شد چون آن فایل از سقف ۷۰۰ خط رد می‌شد، و این قوانین به یک دیالوگ تعلق دارند نه به تب محتوا.
