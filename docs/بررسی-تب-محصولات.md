# تب محصولات — گزارش و تغییرات

---

## این تب چه کار می‌کند

محصول در این پروژه یعنی **فایل یا ویدیوی قابل فروش که به یک مطلب سایت وصل است**. انبار و موجودی در کار نیست (هرچند زیرعنوان صفحه می‌گوید «موجودی انبار»).

```
ادمین محصول می‌سازد
      ↓
انتخاب مطلب از siteData  →  شناسه محصول = شناسه مطلب
      ↓
irHesabdarProducts
      ↓
single-post.js قیمت و قفل دانلود را روی صفحه مطلب اعمال می‌کند
```

همزمان یک همگام‌سازی دوطرفه هم انجام می‌شود: محصول به `downloads` یا `video` همان مطلب در بخش «محتوای سایت» اضافه می‌شود.

---

## 🔴 باگ بحرانی: ویدیوها هرگز به‌عنوان ویدیو شناخته نمی‌شوند

صفحه تک‌مطلب دنبال **دو محصول جدا** می‌گردد:

```js
// scripts/single-post.js:42
videoProduct = prods.find((p) => String(p.id) === String(postId) + "-video");
filesProduct = prods.find((p) => String(p.id) === String(postId));
```

اما فرم افزودن محصول **همیشه** شناسه را برابر شناسه مطلب می‌گذارد:

```js
// scripts/admin/products.js
const newProduct = { id: contentId, ... };
```

هیچ‌جای پنل پسوند `-video` تولید نمی‌شود. نتیجه:

| اتفاق                                   | پیامد                                    |
| --------------------------------------- | ---------------------------------------- |
| ادمین ویدیو اضافه می‌کند                | با شناسه `acc-101` ذخیره می‌شود          |
| صفحه مطلب دنبال `acc-101-video` می‌گردد | پیدا نمی‌کند → **قفل ویدیو کار نمی‌کند** |
| صفحه مطلب `acc-101` را پیدا می‌کند      | آن را **فایل** فرض می‌کند                |
| ادمین بعداً PDF هم اضافه می‌کند         | همان شناسه → **ویدیو بازنویسی می‌شود**   |

یعنی برای یک مطلب نمی‌شود همزمان ویدیو و فایل فروخت — با اینکه کد صفحه مطلب دقیقاً برای همین نوشته شده.

## 🟠 موارد مهم دیگر

### ۱. هیچ کنترل دسترسی‌ای ندارد

برخلاف تب‌های کاربران و مدیریت دسترسی‌ها، این تب **هیچ بررسی نقشی ندارد**:

| عملیات       | مدیر | ادمین                |
| ------------ | ---- | -------------------- |
| افزودن محصول | ✅   | ✅ ← باید محدود شود؟ |
| ویرایش قیمت  | ✅   | ✅ ← ؟               |
| حذف محصول    | ✅   | ✅ ← ؟               |

باید تصمیم بگیرید ادمین چه سطحی داشته باشد.

### ۲. ویرایش فقط قیمت را عوض می‌کند

دکمه «ویرایش قیمت» یک `prompt()` ساده باز می‌کند:

```js
const newPriceRaw = prompt("ویرایش قیمت محصول (تومان):", prod.price);
```

نام، فرمت، آدرس فایل و حجم قابل ویرایش نیستند. برای تغییر آن‌ها باید محصول را دوباره با همان شناسه ثبت کنید تا بازنویسی شود.

ضمناً `prompt()` با بقیه رابط پنل هماهنگ نیست — بقیه جاها مودال دارند.

### ۳. آدرس فایل اعتبارسنجی نمی‌شود

`fileUrl` هر رشته‌ای را می‌پذیرد. یک آدرس اشتباه تا لحظه‌ای که مشتری روی دانلود کلیک کند معلوم نمی‌شود.

### ۴. حذف محصول، خرید مشتری را باطل می‌کند

اگر محصولی حذف شود، کسانی که خریده‌اند در `irHesabdarPurchasedProducts` باقی می‌مانند ولی محصول دیگر وجود ندارد. رفتار صفحه در این حالت مشخص نیست.

### ۵. تصویر محصول ثابت است

```js
img: "../images/ravin.png";
```

همه محصولات همین تصویر را می‌گیرند. فیلدی برای تصویر اختصاصی در فرم نیست.

## ✅ چیزهایی که درست کار می‌کنند

- اتصال محصول به مطلب از طریق `siteData` — انتخاب از فهرست، نه تایپ دستی شناسه
- تشخیص رایگان/پولی و نمایش برچسب سبز «رایگان»
- همگام‌سازی دوطرفه با بخش محتوای سایت
- حذف محصول، فایل مرتبط را از محتوای مطلب هم پاک می‌کند
- عبور همه عملیات از `appApi` — آماده اتصال بک‌اند
- جلوگیری از شناسه تکراری در لایه API (`409`)

# آنچه انجام شد

## ۱. باگ ویدیو رفع شد (راه الف)

شناسه محصول حالا از روی فرمت ساخته می‌شود:

```js
productIdFor("acc-101", "mp4"); // -> "acc-101-video"
productIdFor("acc-101", "pdf"); // -> "acc-101"
```

نتیجه: یک مطلب می‌تواند همزمان ویدیو و فایل بفروشد، و `single-post.js` هر دو را پیدا می‌کند.

دو تابع کمکی هم اضافه شد:

| تابع                                | کار                            |
| ----------------------------------- | ------------------------------ |
| `productIdFor(contentId, category)` | شناسه محصول از روی مطلب و فرمت |
| `contentIdOf(productId)`            | شناسه مطلب، بدون پسوند         |
| `isVideoProduct(product)`           | آیا این محصول ویدیوی مطلب است  |

**نکته ظریف:** همگام‌سازی با «محتوای سایت» همیشه با شناسه _مطلب_ کار می‌کند نه شناسه محصول. `deleteProduct` قبلاً این دو را یکی می‌گرفت؛ با آمدن پسوند، این اشتباه باعث می‌شد حذف ویدیو به رکورد اشتباهی بنویسد. اصلاح شد.

## ۲. مودال کامل ویرایش

`prompt()` جای خود را به یک مودال داد که نام، فرمت، قیمت، حجم و آدرس فایل را ویرایش می‌کند.

تغییر فرمت بین ویدیو و فایل، شناسه محصول را جابه‌جا می‌کند. چون API عملیات rename ندارد، این کار با حذف رکورد قدیمی و ساخت رکورد جدید انجام می‌شود — به همین ترتیب، چون ساخت زودتر باعث تداخل شناسه می‌شد.

اگر برای همان مطلب و همان فرمت محصولی از قبل باشد، تغییر رد می‌شود.

## ۳. اعتبارسنجی آدرس فایل

`isPlausibleFileUrl` آدرس‌های `http(s)://`، `/`، `../` و `./` را می‌پذیرد و رشته خالی را هم (چون فیلد اختیاری است). یک متن ساده یا `htp://` رد می‌شود.

## ۴. جدول خواناتر

- نشان بنفش «ویدیو» و سبز «فایل»
- نام مطلب مرتبط زیر نام محصول
- جستجو حالا نام مطلب را هم پوشش می‌دهد
- حالت خالی («محصولی برای نمایش وجود ندارد») که قبلاً نبود
- خروجی از `escapeHtml` عبور می‌کند
- زیرعنوان صفحه اصلاح شد — «موجودی انبار» در این پروژه معنا نداشت

## دسترسی ادمین

طبق تصمیم شما، دسترسی کامل باقی ماند. محصولات داده حساسی نیستند.

# سهم بک‌اند‌کار

اندپوینت‌ها بدون تغییر باقی ماندند، فقط قرارداد شناسه مهم است:

```
GET    /api/admin/products
POST   /api/admin/products
PATCH  /api/admin/products/:id
DELETE /api/admin/products/:id
```

شکل محصول:

```json
{
  "id": "acc-101-video",
  "contentId": "acc-101",
  "name": "ویدیوی دوره",
  "category": "mp4",
  "price": 95000,
  "fileUrl": "https://...",
  "fileSize": "۲۵۰ مگابایت",
  "img": "../images/ravin.png"
}
```

⚠️ **قرارداد شناسه:** برای فرمت `mp4` شناسه باید `<contentId>-video` باشد و برای بقیه فرمت‌ها برابر `contentId`. صفحه تک‌مطلب بر همین اساس محصولات را پیدا می‌کند. فیلد `contentId` هم ذخیره می‌شود تا سرور مجبور نباشد شناسه را تجزیه کند.

- **تصویر محصول ثابت است** — همه `ravin.png` می‌گیرند.

# تأیید اتصال محصول به مطلب

سوال: آیا محصولی که در پنل ثبت می‌شود، در جای درست خودش روی مطلب سایت می‌نشیند؟

**بله.** زنجیره کامل با ۲۴ تست بررسی و تأیید شد.

## مسیر داده

```
ادمین محصول را ذخیره می‌کند
        ↓
saveContentOverride(contentId, ...)      نوشتن در irHesabdarItemContent
        ↓
applyContentOverrides(siteData)          ادغام در داده در حافظه
        ↓
single-post.js                           رندر روی صفحه مطلب
```

| فرمت محصول             | جایگاه روی مطلب                    |
| ---------------------- | ---------------------------------- |
| `mp4`                  | `content.video` — پخش‌کننده ویدیو  |
| `pdf` · `zip` · `xlsx` | `content.downloads` — فهرست دانلود |

## آنچه تأیید شد

- ویدیو در جایگاه ویدیو می‌نشیند، فایل در فهرست دانلود
- یک مطلب می‌تواند **همزمان** ویدیو و فایل داشته باشد
- ذخیره دوباره همان فایل، جایگزین می‌شود و تکراری نمی‌سازد
- تغییرات بعد از رفرش باقی می‌مانند
- مطالب دیگر دست‌نخورده می‌مانند
- خروجی برای `renderItemVideo` و `renderItemDownloads` قابل رندر است

## دو نکته ظریف

**۱. زمان‌بندی.** `siteData` فقط یک بار هنگام بارگذاری `data.js` ساخته می‌شود. اگر بعد از ذخیره محصول `applyContentOverrides(siteData)` صدا زده نشود، تغییر روی صفحه دیده نمی‌شود. `admin.js` این کار را انجام می‌دهد — ولی هر کد جدیدی که override بنویسد باید همین را رعایت کند.

**۲. `findSiteItem` مقاله را برنمی‌گرداند.** خروجی آن `{ item, categoryKey, categoryTitle }` است. خواندن `.content` مستقیم از آن `undefined` می‌دهد — که به‌راحتی با «همگام‌سازی خراب است» اشتباه گرفته می‌شود. هنگام نوشتن این تست‌ها دقیقاً همین اتفاق افتاد.

## یک محدودیت طراحی

شناسه فایل از روی شناسه مطلب ساخته می‌شود:

```js
const fileId = "prod-file-" + contentId;
```

یعنی هر مطلب **یک** محصول فایل دارد. اگر برای مطلبی PDF ثبت کنید و بعد ZIP، دومی جایگزین اولی می‌شود. این با قرارداد شناسه محصول سازگار است (همه فرمت‌های غیرویدیویی به یک شناسه می‌رسند)، ولی اگر بخواهید یک مطلب چند فایل جدا بفروشد، باید هر دو جا تغییر کند.
