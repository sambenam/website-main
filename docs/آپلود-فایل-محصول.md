# لینک دانلود محصول — ادمین از کجا بیاوردش؟

سوال درستی است و الان **پاسخ روشنی ندارد**. فیلد فقط یک جعبه متن است با این راهنما:

```
placeholder="https://yoursite.com/downloads/file.pdf"
```

یعنی به ادمین می‌گوییم «آدرس فایل را وارد کن» بدون اینکه بگوییم آن آدرس از کجا می‌آید. اگر فایل روی کامپیوتر خودش باشد، هیچ راهی ندارد.

---

## چرا فرانت‌اند به‌تنهایی نمی‌تواند حلش کند

وسوسه‌کننده است که یک `<input type="file">` بگذاریم و فایل را مثل تصویر پروفایل به `base64` تبدیل کنیم. برای عکس ۵۰ کیلوبایتی جواب می‌دهد، برای فایل محصول نه.

سهمیه `localStorage` در مرورگرها حدود ۵ مگابایت است و `base64` حجم را ۳۳٪ زیاد می‌کند:

| فایل         | حجم واقعی   | بعد از base64 | نتیجه              |
| ------------ | ----------- | ------------- | ------------------ |
| عکس پروفایل  | ۵۰ کیلوبایت | ۶۷ کیلوبایت   | ✅ جا می‌شود       |
| PDF کوچک     | ۲ مگابایت   | ۲.۷ مگابایت   | ⚠️ ۵۳٪ سهمیه       |
| PDF معمولی   | ۱۲ مگابایت  | ۱۶ مگابایت    | ❌ سهمیه پر می‌شود |
| ویدیوی کوتاه | ۱۰۰ مگابایت | ۱۳۳ مگابایت   | ❌ غیرممکن         |
| دوره ویدیویی | ۵۰۰ مگابایت | ۶۶۷ مگابایت   | ❌ غیرممکن         |

دو مشکل دیگر هم دارد:

**۱. فایل فقط روی همان مرورگر می‌ماند.** داده در `localStorage` مرورگر ادمین ذخیره می‌شود؛ هیچ بازدیدکننده‌ای به آن دسترسی ندارد. محصول عملاً قابل دانلود نیست.

**۲. فایل خریدنی، محافظت لازم دارد.** یک آدرس مستقیم و ثابت را می‌شود بین کاربران دست‌به‌دست کرد. کسی که نخریده هم دانلود می‌کند.

پس **آپلود واقعی، کار سرور است.** ولی این به معنای بی‌کار بودن ما نیست.

---

## سه راهی که ادمین همین امروز دارد

### راه ۱ — سرویس ابری (بدون نیاز به بک‌اند) ⭐ برای الان

ادمین فایل را در یکی از این‌ها می‌گذارد و لینک اشتراک‌گذاری می‌گیرد:

| سرویس                  | مناسب برای | نکته                                              |
| ---------------------- | ---------- | ------------------------------------------------- |
| **آپارات**             | ویدیو      | رایگان، ایرانی، بدون محدودیت پهنای باند           |
| **یوتیوب** (نامفهرست)  | ویدیو      | نیازمند فیلترشکن برای کاربر ایرانی                |
| **گوگل درایو**         | فایل       | لینک را روی «هرکسی با لینک» بگذارید               |
| **دراپ‌باکس**          | فایل       | لینک را با `?dl=1` تمام کنید تا مستقیم دانلود شود |
| **آروان‌کلاد / لیارا** | هر دو      | ایرانی، مناسب پروداکشن                            |

**نکته مهم:** پخش‌کننده ویدیوی پروژه از قبل آپارات و یوتیوب را پشتیبانی می‌کند:

```js
// scripts/item-content.js:8
const ITEM_VIDEO_PROVIDERS = ["youtube", "aparat", "file"];
```

اما فرم افزودن محصول این را در دسترس نمی‌گذارد و همیشه `provider: "file"` می‌سازد. یعنی اگر ادمین لینک آپارات وارد کند، به‌جای پخش‌کننده، تگ `<video>` می‌گیرد که کار نمی‌کند. **این یک باگ است و باید رفع شود.**

### راه ۲ — گذاشتن فایل کنار پروژه

اگر فایل‌ها کم و کوچک‌اند، می‌شود پوشه‌ای مثل `files/` کنار `images/` ساخت و آدرس نسبی داد:

```
../files/accounting-101.pdf
```

اعتبارسنجی فعلی این شکل را می‌پذیرد. اما برای هر فایل جدید باید کسی به سرور دسترسی داشته باشد — همان چیزی که می‌خواستیم از ادمین نخواهیم.

### راه ۳ — آپلود واقعی (نیازمند بک‌اند)

آنچه در نهایت لازم است. توضیح در بخش بعد.

---

## آنچه از سمت فرانت‌اند می‌توانم بسازم

بدون هیچ سروری، این‌ها را می‌شود همین حالا اضافه کرد:

### الف) انتخابگر منبع فایل

به‌جای یک جعبه متن خالی، سه گزینه:

```
◉ لینک مستقیم فایل        → همان رفتار فعلی
○ آپارات / یوتیوب          → provider درست تنظیم می‌شود
○ آپلود از دستگاه          → غیرفعال، با توضیح «نیازمند اتصال سرور»
```

گزینه سوم را عمداً غیرفعال می‌گذارم با یک پیام روشن، تا ادمین بداند این قابلیت وجود دارد ولی هنوز فعال نیست — بهتر از اینکه اصلاً نبیندش و گیج شود.

### ب) تشخیص خودکار نوع لینک

اگر ادمین لینک آپارات پیست کند، خودمان `provider` را درست تنظیم کنیم:

```js
aparat.com/v/xxxxx   → provider: "aparat"
youtube.com/watch    → provider: "youtube"
youtu.be/xxxxx       → provider: "youtube"
هر چیز دیگر          → provider: "file"
```

### ج) راهنمای کوتاه داخل فرم

یک متن کمکی زیر فیلد که می‌گوید فایل را کجا آپلود کند و لینک را از کجا بردارد. ادمین لازم نیست مستندات بخواند.

### د) اصلاح لینک‌های رایج

گوگل درایو و دراپ‌باکس لینک «مشاهده» می‌دهند نه «دانلود». می‌شود خودکار تبدیلشان کرد:

```
drive.google.com/file/d/ABC/view
  → drive.google.com/uc?export=download&id=ABC

dropbox.com/s/xxx/file.pdf?dl=0
  → dropbox.com/s/xxx/file.pdf?dl=1
```

## سهم بک‌اند‌کار

### ۱. اندپوینت آپلود

```
POST /api/admin/uploads
Content-Type: multipart/form-data

پاسخ: { "url": "https://cdn.example.com/files/abc123.pdf",
        "size": 12582912,
        "mime": "application/pdf" }
```

فرانت‌اند فرم را می‌فرستد و `url` را در فیلد محصول می‌گذارد.

### ۲. محافظت از فایل خریدنی — مهم‌ترین بخش

آدرس ثابت و عمومی یعنی هر کسی که لینک را داشته باشد دانلود می‌کند، حتی بدون خرید. راه درست، **لینک موقت امضاشده** است:

```
GET /api/downloads/:productId
   → سرور بررسی می‌کند این کاربر محصول را خریده
   → لینکی می‌سازد که مثلاً ۱۰ دقیقه اعتبار دارد
   → { "url": "https://cdn.example.com/f/abc?token=...&expires=..." }
```

اینطور لینک لو رفته هم بعد از چند دقیقه بی‌اثر می‌شود.

### ۳. محدودیت‌هایی که سرور باید بگذارد

- سقف حجم برای هر فایل
- فهرست سفید پسوندها (`pdf`, `zip`, `xlsx`, `mp4`)
- بررسی نوع واقعی فایل، نه فقط پسوند
- اسکن ویروس اگر ممکن است
- نام تصادفی برای فایل ذخیره‌شده، تا کسی نتواند با حدس زدن نام به فایل‌های دیگر برسد

---

## پیشنهاد من

مرحله‌ای پیش برویم:

**الان (بدون بک‌اند):** انتخابگر منبع + تشخیص خودکار آپارات و یوتیوب + راهنمای داخل فرم + اصلاح لینک درایو و دراپ‌باکس. ادمین با آپارات و گوگل درایو کارش راه می‌افتد.

**بعد از آمدن بک‌اند:** گزینه «آپلود از دستگاه» فعال می‌شود و نوار پیشرفت می‌گیرد. بقیه فرم دست نمی‌خورد.

اولویت فوری، **رفع باگ آپارات** است: پخش‌کننده پشتیبانی می‌کند ولی فرم محصول اجازه استفاده نمی‌دهد.

# آنچه انجام شد

## سمت ادمین (بدون نیاز به بک‌اند)

| قابلیت                                   | وضعیت             |
| ---------------------------------------- | ----------------- |
| انتخابگر منبع فایل (سه گزینه)            | ✅                |
| تشخیص خودکار آپارات و یوتیوب             | ✅ **باگ رفع شد** |
| تبدیل لینک گوگل درایو به دانلود مستقیم   | ✅                |
| تبدیل لینک دراپ‌باکس (`dl=0` → `dl=1`)   | ✅                |
| هشدار برای ویدیوی روی سرور خودی          | ✅                |
| هشدار حجم بالای ۵۰ مگابایت               | ✅                |
| انتخاب تصویر محصول با پیش‌نمایش          | ✅                |
| سقف ۳۰۰ کیلوبایت برای تصویر با پیام روشن | ✅                |
| راهنمای متنی داخل فرم                    | ✅                |

### باگ آپارات — قبل و بعد

پخش‌کننده پروژه از قبل آپارات را پشتیبانی می‌کرد، ولی فرم محصول همیشه `provider: "file"` می‌ساخت:

```
قبل:  لینک آپارات  →  <video src="aparat.com/v/x">   ❌ صفحه خالی
بعد:  لینک آپارات  →  <iframe src="aparat.com/...">  ✅ پخش‌کننده واقعی
```

با تست انتها به انتها تأیید شد.

## سمت بک‌اند — باقی‌مانده

### ۱. اندپوینت آپلود

```
POST /api/admin/uploads      (multipart/form-data)
پاسخ: { url, size, mime }
```

فرانت‌اند فایل را می‌فرستد و `url` برگشتی را در فیلد محصول می‌گذارد. گزینه «آپلود از دستگاه» در فرم آماده است و فقط باید فعال شود.

### ۲. پردازش تصویر

ادمین تصویر خام آپلود می‌کند، سرور سه نسخه می‌سازد:

| نسخه     | ابعاد    | حجم هدف       | کاربرد        |
| -------- | -------- | ------------- | ------------- |
| `thumb`  | ۲۰۰×۲۰۰  | ~۱۵ کیلوبایت  | فهرست دوره‌ها |
| `medium` | ۶۰۰×۴۰۰  | ~۶۰ کیلوبایت  | کارت محصول    |
| `large`  | ۱۲۰۰×۸۰۰ | ~۱۵۰ کیلوبایت | صفحه مطلب     |

فرمت خروجی WebP با fallback به JPG.

### ۳. محافظت از فایل خریدنی ⚠️ مهم‌ترین

آدرس ثابت یعنی هر کسی لینک را داشته باشد دانلود می‌کند، حتی بدون خرید:

```
GET /api/downloads/:productId
   → بررسی اینکه این کاربر محصول را خریده
   → ساخت لینک با اعتبار محدود (مثلاً ۱۰ دقیقه)
   → { "url": "https://cdn/f/abc?token=...&expires=..." }
```

### ۴. محدودیت‌های سرور

- سقف حجم برای هر فایل
- فهرست سفید پسوندها: `pdf` `zip` `xlsx` `mp4` `jpg` `png` `webp`
- بررسی نوع واقعی فایل (magic bytes)، نه فقط پسوند
- نام تصادفی برای فایل ذخیره‌شده
- اسکن ویروس در صورت امکان
