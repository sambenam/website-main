# جستجوی سریع در سیستم

کادر جستجوی بالای پنل، در همه بخش‌ها همزمان می‌گردد.

---

## وضعیت قبل

کادر فقط یک placeholder داشت. **هیچ کدی به آن وصل نبود** — تایپ کردن هیچ اتفاقی نمی‌انداخت:

```bash
grep -n "globalSearch" scripts/admin/search.js
# >>> هیچ نتیجه‌ای
```

## کجاها را می‌گردد

| بخش              | فیلدهای قابل جستجو                     | کلیک روی نتیجه     |
| ---------------- | -------------------------------------- | ------------------ |
| کاربران          | نام، ایمیل، شناسه، نقش، وضعیت، تلفن\*  | مودال ویرایش کاربر |
| مدیریت دسترسی‌ها | نام، ایمیل، شناسه، نقش، تلفن\*         | مودال ویرایش عضو   |
| محصولات          | نام، شناسه، نوع فایل، مطلب مرتبط       | مودال ویرایش محصول |
| سفارشات          | شماره سفارش، مشتری، محصول، ایمیل، مبلغ | مودال جزئیات سفارش |
| محتوای سایت      | عنوان، شناسه، دسته                     | ویرایشگر محتوا     |
| پیام‌ها          | فرستنده، ایمیل، متن پیام، موضوع        | مودال خواندن پیام  |

\* تلفن فقط برای مدیر — توضیح زیر.

## حریم خصوصی

تب کاربران شماره تلفن را برای ادمین ماسک می‌کند (`۰۹۱۲•••••`). اگر جستجو روی شماره کامل تطبیق می‌داد، **یک ادمین می‌توانست با حدس زدن شماره را تأیید کند** — دقیقاً همان چیزی که ماسک برای جلوگیری از آن هست.

```
مدیر با «09129998877»   →  پیدا می‌کند   ✅
ادمین با «09129998877»  →  پیدا نمی‌کند  ✅
ادمین با «زهرا»         →  پیدا می‌کند   ✅
```

همچنین دکمه‌های عملیات هم فیلتر می‌شوند: ادمین نتیجه کاربر را می‌بیند ولی دکمه ویرایش نمی‌گیرد، چون در تب کاربران هم اجازه‌اش را ندارد.

---

## نکات کاربردی

**ارقام فارسی و انگلیسی یکی هستند.** جستجوی `۷۰۱` و `701` هر دو سفارش `#۷۰۱` را پیدا می‌کنند.

**املای عربی و فارسی یکی هستند.** `کريمي` با `ي` عربی، `زهرا کریمی` را پیدا می‌کند. همین‌طور `ك` عربی با `ک` فارسی.

**صفحه‌کلید:**

- `↓` و `↑` — حرکت بین نتایج
- `Enter` — باز کردن نتیجه انتخاب‌شده (یا اولی)
- `Esc` — بستن

**حداقل دو حرف** لازم است. با یک حرف نیمی از پنل نتیجه می‌شد.

**حداکثر ۵ نتیجه از هر بخش** نمایش داده می‌شود تا یک لیست شلوغ بقیه را کنار نزند. اگر بیشتر بود، «۳ مورد دیگر» نوشته می‌شود.

---

## باگی که موقع ساخت پیدا شد

فلش پایین به‌جای یک ردیف، **دو ردیف** جلو می‌رفت. علتش این بود که در بعضی شرایط `initGlobalSearch()` دو بار اجرا می‌شد و هر کلید دو بار پردازش می‌شد. با یک نشانگر `data-search-bound` روی خود کادر، فقط یک بار بایند می‌شود.

---

## برای بک‌اند

جستجو فعلاً سمت کلاینت روی `appState` انجام می‌شود. با حجم فعلی داده مشکلی ندارد.

اگر تعداد رکوردها زیاد شد، یک اندپوینت بسازید:

```js
GET /admin/search?q=...
```

**نکته امنیتی:** سرور باید همان قانون دسترسی را اعمال کند — یعنی برای درخواستی که از حساب ادمین می‌آید، **نباید** روی فیلد تلفن جستجو کند و **نباید** شماره را در پاسخ برگرداند.

شکل پاسخ مورد انتظار:

```js
[
  {
    type: "order", // user|staff|product|order|content|message
    items: [
      {
        title: "#۷۰۱",
        subtitle: "زهرا کریمی · دوره اکسل",
        badge: "پرداخت موفق",
      },
    ],
    total: 12,
  },
];
```
