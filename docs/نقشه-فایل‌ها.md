# نقشه فایل‌ها — دنبال چه چیزی می‌گردی؟

> یک صفحه برای پیدا کردن سریع کد. اگر می‌خواهی چیزی را عوض کنی، اینجا را نگاه کن.

---

## می‌خواهم چیزی را عوض کنم…

| چه چیزی؟                | کجا؟                                                |
| ----------------------- | --------------------------------------------------- |
| **آدرس سرور بک‌اند**    | `scripts/api.js` — دو خط `APP_CONFIG` بالای فایل    |
| فهرست اندپوینت‌ها       | `scripts/api.js` — شیء `appApi` انتهای فایل         |
| رفتار یکی از تب‌های پنل | `scripts/admin/<نام تب>.js`                         |
| یک فرم داخل پنل         | `scripts/admin/modals.js`                           |
| ظاهر یک بخش از پنل      | `styles/pages/admin-<نام بخش>.css`                  |
| متن یا ساختار یک صفحه   | `html/<نام صفحه>.html`                              |
| فهرست دوره‌ها و مقالات  | `scripts/main-items.js` و `scripts/header-items.js` |
| ظرفیت بخش‌های صفحه اصلی | `scripts/home-slots.js` — جدول `HOME_SLOTS`         |
| منوی هدر یا فوتر        | داخل خود فایل HTML — در هر شش صفحه یکسان است        |

## سه قانونی که موقع تقسیم فایل باید رعایت شود

هر سه با اجرای واقعی کد ثابت شده‌اند، نه حدس:

**۱. `const` هم‌نام در دو فایل = فاجعه بی‌صدا**

مرورگر `SyntaxError` می‌دهد و **کل فایل دوم را دور می‌اندازد**:

```
نتیجه: c1 ok | c3 ok | c4 ok        ← c2 اصلاً اجرا نشد
SyntaxError: Identifier 'DUP' has already been declared
```

دو `function` هم‌نام مشکلی ندارند — دومی برنده می‌شود.

**۲. کدی که هنگام لود اجرا می‌شود، باید به فایل قبلی نیاز داشته باشد نه بعدی**

```
ReferenceError: resolveCurrentStaffId is not defined
```

فراخوانی داخل بدنه تابع مشکلی ندارد — تا وقتی کاربر کلیک کند، همه فایل‌ها لود شده‌اند. فقط `const X = f()` در سطح فایل خطرناک است.

**۳. یک خطای بدون `try` = مرگ بقیه فایل**

`<script>` معمولی در اولین خطای گرفته‌نشده متوقف می‌شود. در `up-btn.js` این یعنی کل فایل، ولی در فایل بلندتر یعنی هر خطی که پایین‌تر بود.

## تور ایمنی

```bash
node tests/file-split.test.js        # ۱۸۷ تست، فقط درباره تقسیم فایل
for f in tests/*.test.js; do node "$f"; done    # کل ۱۵۰۱ تست
```

`tests/file-split.test.js` هشت چیز را نگه می‌دارد:

1. هیچ نام سراسری تکراری نیست
2. هیچ فایلی هنگام لود به فایل بعدی نیاز ندارد
3. هر اسکریپت HTML روی دیسک هست، و هیچ اسکریپت یتیمی نمانده
4. هیچ فایلی از ۸۰۰ خط (JS) یا ۷۰۰ خط (CSS) رد نشده
5. هر استایل HTML موجود است و همه `@import`ها مقصد دارند
6. هر تابعی که HTML با `onclick` صدا می‌زند واقعاً وجود دارد
7. صفحه ادمین با همه استایل‌ها بالا می‌آید و متغیرها حل می‌شوند
8. **هر ۱۱ صفحه روی سرور HTTP واقعی بدون خطا اجرا می‌شوند**

مورد هشتم بلافاصله یک باگ واقعی گرفت: `up-btn.js` روی سه صفحه که دکمه‌اش را ندارند، `TypeError` می‌داد.

## اضافه کردن فایل جدید

1. فایل را در پوشه مناسب بساز
2. تگ `<script>` یا `<link>` را در HTML اضافه کن — **جای درست در ترتیب**
3. `node tests/file-split.test.js` را بزن

قدم سوم لازم نیست یادت بماند کدام تست را به‌روز کنی: کمک‌کننده `tests/helpers/page-scripts.js` ترتیب را مستقیم از خود HTML می‌خواند، پس هر ۲۶ فایل تست خودکار همراه می‌شوند.
