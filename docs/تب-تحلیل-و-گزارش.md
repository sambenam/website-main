# تب تحلیل و گزارش

هر عددی که در این تب دیده می‌شود از یک تب دیگر خوانده می‌شود. هیچ عدد ساختگی یا نمونه‌ای در این تب وجود ندارد.

---

## منبع هر عدد

| کارت                 | از کجا خوانده می‌شود       | فرمول                         | کلیک روی آن                                                                |
| -------------------- | -------------------------- | ----------------------------- | -------------------------------------------------------------------------- |
| میانگین مبلغ هر خرید | سفارشات موفق               | درآمد موفق‌ها ÷ تعداد موفق‌ها | در همان تب می‌ماند، نمودار فروش برجسته می‌شود                              |
| نرخ لغو سفارشات      | باکس «لغو شده» تب سفارشات  | لغوشده‌ها ÷ کل سفارشات        | می‌رود به تب سفارشات، فیلتر روی «لغو شده»، باکس لغوشده ۴ ثانیه چشمک می‌زند |
| کل محصولات و دوره‌ها | تب محصولات                 | تعداد ردیف‌های جدول محصولات   | می‌رود به تب محصولات                                                       |
| نمودار فروش ماهیانه  | تاریخ سفارشات موفق         | جمع مبلغ به تفکیک ماه شمسی    | مودال بزرگ با دکمه دانلود اکسل                                             |
| سه دوره پرفروش       | آیتم‌های داخل سفارشات موفق | تعداد فروش هر محصول           | مودال کامل (تا ۱۲ مورد) + دانلود اکسل                                      |

## نکات مهم محاسبات

### فقط سفارش موفق پول است

میانگین خرید، نمودار فروش و پرفروش‌ها **فقط** از سفارش‌های `success` محاسبه می‌شوند. سفارش ناموفق و لغوشده در هیچ‌کدام از این سه شمرده نمی‌شوند.

### ناموفق ≠ لغوشده

نرخ لغو فقط سفارش‌های `cancelled` را می‌شمارد — یعنی دقیقاً همان عددی که در باکس «لغو شده» تب سفارشات می‌بینید.

پیش از این، سفارش‌های ناموفق (`failed`) هم لغو حساب می‌شدند و کارت گزارش با باکس سفارشات اختلاف داشت. مثال واقعی: ۷ سفارش با ۲ لغو و ۱ ناموفق، کارت **۴۳٪** نشان می‌داد در حالی که باکس سفارشات ۲ تا داشت. حالا هر دو **۲۹٪** می‌گویند.

### پرفروش‌ها از آیتم‌های سفارش خوانده می‌شود، نه از نام سفارش

وقتی مشتری دو محصول را با هم می‌خرد، فیلد `product` سفارش می‌شود:

```
"دوره اکسل، جزوه مالیات"
```

اگر روی همین رشته گروه‌بندی کنیم، یک محصول جعلی به اسم «دوره اکسل، جزوه مالیات» ساخته می‌شود و دو محصول واقعی گم می‌شوند. مثال واقعی:

| قبل (غلط)                       | بعد (درست)           |
| ------------------------------- | -------------------- |
| «دوره اکسل، جزوه مالیات» ۱ فروش | «دوره اکسل» ۲ فروش   |
| «دوره اکسل» ۱ فروش              | «جزوه مالیات» ۱ فروش |

حالا از آرایه `items[]` داخل سفارش خوانده می‌شود که تک‌تک محصولات را جدا دارد. سفارش‌های قدیمی که `items` ندارند، از روی همان `product` شمرده می‌شوند تا از گزارش حذف نشوند.

ترتیب: **تعداد فروش**. اگر دو محصول تعداد برابر داشتند، آن‌که درآمد بیشتری ساخته بالاتر می‌آید.

### ماه‌ها با ارقام فارسی

`api.js` تاریخ را این‌طور می‌نویسد: `۱۴۰۵/۰۵/۰۱`

دستور `parseInt("۰۵")` در جاوااسکریپت **NaN** برمی‌گرداند، نه ۵. به همین دلیل هیچ سفارش واقعی در نمودار نمی‌افتاد و همه ستون‌ها صفر بودند. تابع `orderMonthIndex()` اول ارقام را به انگلیسی تبدیل می‌کند.

این تابع هر دو حالت را می‌پذیرد (`۱۴۰۵/۰۵/۰۱` و `1405/05/01`) و جداکننده `/`، `-` و `.` را می‌فهمد. تاریخ خراب یا ماه خارج از ۱ تا ۱۲ نادیده گرفته می‌شود.

## نمودار فروش

هر ۱۲ ماه سال همیشه نمایش داده می‌شود، حتی ماه‌های بدون فروش. ماه صفر یک نوار خاکستری نازک می‌گیرد تا محور خوانا بماند.

بلندترین ستون ۱۰۰٪ ارتفاع می‌گیرد و بقیه نسبت به آن. عدد بالای هر ستون به هزار تومان است (`۹۸K` یعنی ۹۸ هزار تومان)، و مبلغ کامل در tooltip نمایش داده می‌شود.

## توابع قابل استفاده برای بک‌اند

همه در `scripts/admin/analytics.js`:

```js
orderMonthIndex(order); // شماره ماه شمسی ۰ تا ۱۱، یا null
revenueByMonth(orders); // آرایه ۱۲ تایی، ایندکس ۰ = فروردین
bestsellingProducts(orders); // [{ name, count, revenue }] مرتب‌شده
totalProductCount(); // تعداد محصولات
cancelledOrders(orders); // فقط سفارش‌های لغوشده
calculateRevenue(orders); // جمع مبلغ سفارش‌های موفق
```

اگر بک‌اند بعداً بخواهد این محاسبات را سمت سرور انجام دهد، کافی است یک اندپوینت برگرداند با همین شکل:

```json
{
  "averageOrderValue": 544286,
  "cancelRate": 20,
  "totalProducts": 5,
  "revenueByMonth": [0, 490000, 780000, 1900000, 640000, 0, 0, 0, 0, 0, 0, 0],
  "bestsellers": [
    { "name": "دوره حسابداری مقدماتی", "count": 3, "revenue": 1470000 }
  ]
}
```

نکته برای بک‌اند: `revenueByMonth` باید آرایه ۱۲ تایی باشد و ایندکس ۰ فروردین است.

## چیزی که در سفارش لازم است

برای اینکه گزارش درست کار کند، هر سفارش باید این‌ها را داشته باشد:

```js
{
  status: "success" | "failed" | "cancelled",
  amount: 490000,              // عدد، نه رشته
  date:   "۱۴۰۵/۰۵/۰۱",        // شمسی
  items: [                     // برای پرفروش‌ها ضروری است
    { id: "p1", name: "دوره حسابداری مقدماتی", price: 490000, qty: 1 }
  ]
}
```

اگر `qty` نباشد، ۱ فرض می‌شود.
