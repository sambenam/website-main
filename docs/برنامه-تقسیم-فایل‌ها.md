## ۳. چرا این کار **امن** است — اثبات با اجرای واقعی

نگرانی اصلی: «اگر یک فایل را به ده تا بشکنیم، آیا کد می‌شکند؟»

پاسخ: **نه** — چون همه `<script>`های معمولی در مرورگر **یک اسکوپ سراسری مشترک** دارند.
این را با jsdom اجرا کردم، نه حدس زدم:

```
فایل a.js:  const SHARED_CONST = "from-a";  function fnFromA(){...}
فایل b.js:  می‌خواند SHARED_CONST و صدا می‌زند fnFromA()

خروجی واقعی:
  a executed, typeof fnFromB = undefined     ← فایل بعدی هنوز لود نشده
  b sees SHARED_CONST = from-a               ✓
  b sees fnFromA() = a-fn                    ✓
  b sees sharedLet = 1                       ✓
```

**پس تنها یک قانون وجود دارد که باید رعایت شود:**

> تابعی که _هنگام لود شدن فایل_ صدا زده می‌شود، باید در فایلی باشد که **بعد از** فایل تعریف تابع بیاید.

این را هم تست کردم — وقتی نقض شود، دقیقاً این خطا می‌آید:

```
خطای زمان لود: ReferenceError — resolveCurrentStaffIdSim is not defined
```

### در `admin.js` فقط **۵ نقطه** چنین وابستگی‌ای دارند

با اسکن خودکار پیدا شدند:

|    خط | متغیر                   | توابعی که هنگام لود صدا می‌زند                                                                                  |
| ----: | ----------------------- | --------------------------------------------------------------------------------------------------------------- |
|   ۳۵۸ | `currentAdminUserRole`  | `readAdminRole`                                                                                                 |
|   ۷۹۲ | `appState`              | `loadDynamicUsers`, `loadDynamicProducts`, `loadDynamicOrders`, `loadAdminNotifications`, `loadDynamicMessages` |
|   ۸۰۴ | `currentStaffProfileId` | `resolveCurrentStaffId`                                                                                         |
| ۱٬۰۴۱ | `announcedEvents`       | `loadAnnouncedIds`                                                                                              |
| ۴٬۱۱۴ | `checkFileUrl`          | `detectUrlSource`, `toPersianDigits`                                                                            |

بقیه ۵۳۴ ارجاع متقابل (از مجموع ۵۳۹) داخل بدنه توابع هستند و **فقط موقع کلیک کاربر** اجرا می‌شوند — یعنی وقتی همه فایل‌ها لود شده‌اند. برای آن‌ها ترتیب کاملاً بی‌اهمیت است.

### یک دام واقعی که باید مواظبش بود

اگر یک `const` هم‌نام در دو فایل تعریف شود، مرورگر کل فایل دوم را دور می‌اندازد:

```
نتیجه: c1 ok | c3 ok | c4 ok        ← c2 اصلاً اجرا نشد
خطاها: SyntaxError: Identifier 'DUP' has already been declared
```

الان در ده فایل صفحه ادمین فقط **یک نام تکراری** وجود دارد:
`escapeHtml` در `item-content.js:22` و `admin-content.js:1548`.
هر دو `function` هستند (نه `const`) و بدنه‌شان یکسان است، پس مشکلی نمی‌سازند — ولی موقع تقسیم باید حواسم باشد تعداد این‌ها زیاد نشود.

## ۵. شبکه ایمنی — چطور ثابت کنم چیزی خراب نشده

سه لایه، پشت سر هم:

**۱. اثر انگشت محتوا** — نشان می‌دهد حتی یک خط کد هم گم یا عوض نشده.
همین حالا محاسبه کردم:

```
admin.js  → ۴٬۶۰۳ خط غیرخالی، sha256: 3939345ee59ccf1d
admin.css → ۲٬۴۸۷ خط غیرخالی، sha256: 1e6b4ebb78409433
```

اثبات کردم که این عدد به تقسیم حساس نیست — همان فایل را به سه تکه شکستم و حتی با ترتیب معکوس چسباندم:

```
سه تکه (ترتیب معکوس) → ۴٬۶۰۳ خط، 3939345ee59ccf1d  ✓ یکسان
```

پس اگر بعد از تقسیم این هش عوض شود، یعنی کد را دست‌کاری کرده‌ام — و باید برگردم.

**۲. تست جدید `tests/file-split.test.js`** که بررسی می‌کند:

- هیچ نام سراسری‌ای بین فایل‌های جدید تکراری نشده (دام `SyntaxError`)
- ترتیب `<script>` در HTML با وابستگی‌های زمان لود سازگار است
- هیچ فایلی از ۸۰۰ خط رد نشده
- هر ده صفحه در jsdom بدون `ReferenceError` بالا می‌آیند

**۳. همان ۱۳۲۵ تست فعلی** — الان اجرا کردم، همه سبز:

```
۲۶ فایل تست · ۱۳۲۵ ✓ · ۰ ✗
```

⚠️ نکته‌ای که باید همراهش حل شود: **۲۰ فایل تست از ۲۶ تا، فهرست اسکریپت‌ها را دستی داخل خودشان نوشته‌اند:**

```js
const FILES = ['api.js','app-shell.js','header-items.js', ...];
```

اگر فایل‌ها را بشکنم و این را درست نکنم، هر ۲۰ تا می‌شکنند. راه‌حل: یک کمک‌کننده مشترک `tests/helpers/boot-admin.js` که ترتیب را **مستقیم از خود `admin.html` می‌خواند** — اینطور دیگر هیچ‌وقت از واقعیت عقب نمی‌ماند. تست کردم که خواندنش کار می‌کند:

```
ترتیب واقعی خوانده‌شده از admin.html:
api.js → app-shell.js → header-items.js → item-content.js → main-items.js
→ item-store.js → home-sections.js → data.js → admin-content.js → admin.js → up-btn.js
```
