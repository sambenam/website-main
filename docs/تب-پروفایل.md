# تب پروفایل

ادمین و مدیر می‌توانند پروفایل خودشان را ویرایش کنند. هر تغییری فقط به مدیرها اطلاع داده می‌شود و در مدیریت دسترسی‌ها ثبت می‌گردد.

---

## دو راه ورود

| نقطه کلیک    | کجاست                           |
| ------------ | ------------------------------- |
| آیکون آدمک   | بالا سمت چپ، کنار زنگوله و پاکت |
| کارت پروفایل | پایین سایدبار، سمت راست         |

هر دو `switchView('profile')` صدا می‌زنند. هر دو از قبل وصل بودند.

---

## چه چیزی قابل ویرایش است

- نام کاربری
- ایمیل
- تلفن همراه
- تصویر پروفایل
- رمز عبور (با تأیید رمز فعلی)

قبل از ذخیره، یک مودال بازبینی ۱۵ ثانیه‌ای مقادیر قبل و بعد را نشان می‌دهد.

---

## قانون اطلاع‌رسانی

```
ادمین یا مدیر پروفایلش را عوض می‌کند
        ↓
اعلان از نوع staff ساخته می‌شود   ← همیشه، صرف‌نظر از اینکه چه کسی تغییر داده
        ↓
فقط مدیرها آن را می‌بینند         ← ادمین اعلان خودش را هم نمی‌بیند
        ↓
در تب اعلان‌ها و زنگوله ثبت می‌شود
        ↓
در مدیریت دسترسی‌ها → لیست تغییرات هم می‌نشیند
```

### چه کسی چه اعلانی می‌بیند

| نوع اعلان                 | ادمین | مدیر |
| ------------------------- | :---: | :--: |
| سفارش و پرداخت            |  ✅   |  ✅  |
| ثبت‌نام کاربر جدید        |  ✅   |  ✅  |
| حذف حساب مدیریت           |  ✅   |  ✅  |
| **تغییر پروفایل کارکنان** |  ❌   |  ✅  |
| **گزارش تخلف**            |  ❌   |  ✅  |

---

## باگ‌هایی که رفع شد

### ۱. تغییر پروفایل ادمین اصلاً ثبت نمی‌شد

مهم‌ترین باگ. تابع `pushAdminNotification` این خط را داشت:

```js
if (!canReceiveNotification({ type })) return null; // ← اعلان ساخته نمی‌شد
```

این دو مفهوم کاملاً متفاوت را قاطی کرده بود:

- **چه کسی اعلان را می‌بیند؟** → باید فقط مدیرها باشند
- **آیا اعلان ساخته شود؟** → باید همیشه ساخته شود

چون ادمین حق دیدن اعلان `staff` را ندارد، وقتی خودش پروفایلش را عوض می‌کرد **هیچ رکوردی ساخته نمی‌شد** و مدیر هرگز خبردار نمی‌شد. یعنی دقیقاً همان حالتی که این قابلیت برایش وجود دارد، کار نمی‌کرد.

تست واقعی قبل از رفع:

```
ادمین پروفایلش را عوض می‌کند  →  اعلان: ۰  ❌
مدیر پروفایلش را عوض می‌کند   →  اعلان: ۱  ✅
```

حالا اعلان همیشه ساخته و ذخیره می‌شود؛ `visibleNotifications()` تصمیم می‌گیرد چه کسی ببیند.

### ۲. اعلان‌ها ماندگار نبودند

اعلان‌ها فقط در حافظه بودند. یعنی ادمین تغییر می‌داد، رکورد ساخته می‌شد، ولی تا مدیر وارد شود یا صفحه رفرش شود — رکورد از بین می‌رفت. حالا در `irHesabdarNotifications` ذخیره می‌شوند (حداکثر ۲۰۰ مورد اخیر).

### ۳. بلوک آزمایشی، اعلان‌های واقعی را پاک می‌کرد

در هر بار لود پنل این اجرا می‌شد:

```js
setTimeout(function () {
  appState.notifications = [];        // ← همه چیز پاک
  pushAdminNotification(...)          // ۷ اعلان ساختگی
}, 700);
```

یعنی حتی اگر دو باگ بالا نبودند، اعلان واقعی با رفرش بعدی نابود می‌شد.

### ۴. لاگ تغییرات با تأخیر و مشروط نوشته می‌شد

ثبت در مدیریت دسترسی‌ها داخل تایمر ۸ ثانیه‌ای `markStaffRecentlyUpdated()` بود که **فقط وقتی مدیر وارد تب دسترسی‌ها می‌شد** اجرا می‌شد. اگر ادمین تغییر می‌داد و کسی سراغ آن تب نمی‌رفت، هیچ ردی نمی‌ماند.

حالا `applyStaffProfileChanges()` بلافاصله می‌نویسد.

### ۵. نقش کاربر تا پایان بارگذاری اشتباه بود

`currentStaffProfileId` تا وقتی `hydrateFromApi()` تمام شود عدد ثابت ۱ بود. یعنی در آن فاصله **یک ادمین به‌عنوان اولین مدیر شناخته می‌شد** و هر بررسی نقشی در آن بازه — از جمله دسترسی اعلان‌ها — جواب غلط می‌داد.

### ۶. داده آزمایشی در مدیریت دسترسی‌ها

دو ردیف تغییر ساختگی برای کاربر شماره ۲ به‌همراه نقطه قرمز «بازبینی» از قبل نوشته شده بود، پس تب دسترسی‌ها تغییراتی را نشان می‌داد که هرگز اتفاق نیفتاده بودند.

---

## آنچه در لاگ ثبت می‌شود

هر فیلد تغییرکرده یک ردیف جدا:

```js
{
  date: "۱۴۰۵/۰۵/۰۶, ۹:۳۳:۱۲",
  text: "تلفن همراه خود را تغییر داد.",
  change: { label: "تلفن همراه", before: "۰۹۱۲۲۲۲۲۲۲۲", after: "۰۹۱۲۹۹۹۹۹۹۹" }
}
```

در مودال «لیست تغییرات» با رنگ قرمز (قبل) و سبز (بعد) نمایش داده می‌شود.

## برای بک‌اند

اعلان‌ها فعلاً در `localStorage` با کلید `irHesabdarNotifications` ذخیره می‌شوند.

```js
GET / admin / notifications;
```

**نکته امنیتی مهم:** سرور باید همان قانون دسترسی را اعمال کند و ردیف‌های `staff` و `report` را برای ادمین‌ها **اصلاً نفرستد**. فیلتر سمت کلاینت فقط برای نمایش است و نباید به آن اتکا شود.

شکل رکورد:

```js
{
  id: 1754899200000,
  type: "staff",              // purchase | user | staff | report | deletion
  title: "تغییر پروفایل عضو مدیریت",
  desc: "«محمد رضایی» نام کاربری، تلفن همراه را به‌روزرسانی کرد.",
  createdAt: 1754899200000,
  unread: true,
  details: {
    "کاربر": "محمد رضایی",
    "شناسه کاربر": "#۲",
    "نقش": "ادمین",
    "موارد تغییرکرده": "نام کاربری، تلفن همراه",
    "جزئیات تغییرات": "نام کاربری: محمد رضایی → محمد رضایی‌منش",
    "زمان تغییر": "۱۴۰۵/۰۵/۰۶, ۹:۳۳",
    "نشانی IP": "در انتظار اتصال به سرور"
  }
}
```

فیلد «نشانی IP» عمداً خالی است — سرور باید پرش کند.

## آنچه هنوز مانده

- **تصویر پروفایل** از `pravatar.cc` می‌آید که در ایران ممکن است بالا نیاید
- **آپلود تصویر** فعلاً در `localStorage` می‌ماند، نه روی هاست
- **نشانی IP** تا اتصال بک‌اند خالی است
